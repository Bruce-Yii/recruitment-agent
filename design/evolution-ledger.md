# Recruitment OS 全程迭代与决策台账（完整流水账）

> **说明**：本台账按真实时间顺序，完整记录 Recruitment OS 从最初的粗原型出发，历经需求去噪、架构对齐、交互推翻重来、视觉审美突围、三层递进导航定型、像素级细节死磕、极端业务与前端压测，直至工程切分与 UI 冻结交付的**全部演进过程**。台账不依赖云端临时文件名或内部版本号，只以真实的“每一轮遇到了什么问题 → 怎么讨论拍板 → 砍掉了什么 → 做成了什么”如实归档，方便后续随时复盘。

## 第一部分：完整迭代流水账（按时间线逐轮记录）

### 第 1 轮：起步与“去伪存真”——先砍掉脱离真实招聘的伪需求

* **初始起点**：最早一版前端工作台原型偏“演示噱头”，里面放了两个脱离真实科技公司招聘场景的功能：一个是“模糊扫描件简历纠偏识别”，另一个是按角色字段脱敏的“RBAC 隐私权限拦截”。

* **核心纠偏**：你直接拍死了这两处伪需求——真实科技公司收到的几乎都是高清 PDF / Word 电子简历，极少存在扫描件纠偏需求；且在业务早期（对应后端仓库既定规则 `D-33`），团队成员需要全局可见以保证协作效率，不需要在 v1.0 强行做 RBAC 字段拦截。

* **本轮沉淀**：确立了“**真实高清电子简历 + 全局透明协作（角色只做视角过滤、不做权限拦截）**”的产品基线，把注意力从“炫技”拉回真实招聘场景。

### 第 2 轮：深挖后端仓库与对齐 2026 生产级 Agent 底座

* **做了什么**：完整通读后端 `recruitment-agent` 仓库文档与架构设计（基于 DSH Web + `@recruitment/dsh-recruitment` 30 个工具 + PostgreSQL 17 63 张基础表与 3 张视图 + 本地 PyMuPDF 转换器，覆盖 `S3` 岗位/标准、`S6` 简历入池、`S7` 初筛、`S8` 约面、`S9` 妙记、`S10` 面评与决策）。

* **发现的缺口**：后端常规线性主干很扎实（包括 `D-79/D-101` 失败关闭审批闸门、`D-95` 对话内原样确认与 SHA-256 防篡改、面评严禁求平均分、`E1–E4` 端到端验收标准），但缺真实业务高频出现的**非标流转**（跨岗调剂、临时加面、跳轮豁免）以及 **Offer 邮件外发闭环**。

* **底层架构拍板**：确立「**原子工具 + 4 条极窄硬红线 + 软 SOP**」的 Agent 工程范式，避免把多变的招聘流程写死成刚性状态机；并对照 2026 年生产级 Agent 实践，补齐了 5 块底座规范：

  * [MCP 2026-07 无状态协议与长耗时异步 Tasks 扩展](https://harnessrouter.ai/blog/ai-agent-protocols-2026)

  * [AG-UI 协议的 `STATE_DELTA` 局部状态增量同步](https://github.com/ag-ui-protocol/ag-ui)

  * [A2UI 声明式交互卡片规范](https://a2ui.org/)

  * [Anthropic 上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)与 [Prompt Caching 前缀分层缓存](https://bitpixelcoders.com/blog/building-ai-agents-that-actually-work-a-practical-guide-for-2026)

  * [MLflow 运行时语义评测探针](https://mlflow.org/articles/building-production-ready-ai-agents-in-2026/)

* **阶段交付**：整理输出《后端工程补齐与 2026 架构任务单》，你直接发给了后端工程窗口。

### 第 3 轮：第一次交互大反思——反“替 AI 改作业”与反“窄栏填表”

* **暴露的问题**：早期把原型做出来后，我们一起挑出了三个非常致命的体验硬伤：

  1. 界面上放了一个显眼的「修正第 3 项并批注」快捷按钮；

  2. 点击约面、推下一轮、发邮件等确定性操作时，在右侧窄栏底部硬挤出了一堆内联表单；

  3. 候选人还在初筛阶段，对话框下方却露出了“发 Offer”之类的快捷语，且切换候选人时视图没有同步切到对应阶段。

* **关键洞察**：你一针见血地指出——**初筛阶段人看简历争分夺秒，没人有空帮 AI 改作业、当数据标注员**；而且所有确定性写操作都不该让人在窄栏里手动填表，应该由用户一句话说完，Agent 自动解析后弹出**居中只读模板确认卡**，默认一键确认，真有局部改动再点「微调」。

* **随后自查连修 7 处割裂**：

  1. 切换候选人时自动对齐其真实所处阶段（初筛/一面/二面/终审/已归档），已归档锁定推进动作；

  2. “不通过 / 淘汰”统一收进居中确认弹窗，不再静默裸改状态；

  3. 页面内三处 Agent 入口统一共享同一套对话上下文记忆；

  4. 岗位筛选下拉动态读取实际在招岗位，并补上空岗位引导态；

  5. 工作台统计数字与日期改为实时计算，不再写死假数字；

  6. 连续审阅切换器上移至顶部，彻底释放下方阅读空间；

  7. 支持键盘 `Esc` 一键关闭弹窗。

### 第 4 轮：横向深挖真实高频招聘业务 6 大维度

* **思考升级**：修完局部交互后，我们跳出单点修补，系统盘点了真实招聘团队每天高频碰到的 6 个横向维度，沉淀为《产品架构与交互设计规范》并获得你的认可：

  1. **多角色视角切换**：HR / 用人经理 / 面试官看同一份数据，只切换关注焦点（如待跟进、待拍板、待面试），不做权限阻断；

  2. **SLA 停留时长与超时预警**：标注候选人在当前环节停留了几天，超过阈值自动温和标黄/标红，避免好候选人被晾在池子里；

  3. **Agent 静默代办 vs 人工拍板的白盒边界**：解析简历、拉取妙记、同步状态等低风险动作 Agent 静默完成并记入“Agent 已代办”；约面发邀请、发淘汰信、发 Offer、改标准等高风险外部动作必须走“等你拍板”白盒确认；

  4. **非结构化碎片信息即时捕捉**：微信聊天、电话沟通过的薪资底线、到岗时间、手头竞品 Offer 等碎片约束，允许随时一句话丢给 Agent，立刻沉淀并置顶在候选人档案里；

  5. **HC 名额约束与批量流转**：盯住每个岗位的 `已发 Offer / 总 HC` 进度，支持初筛池勾选后批量推进或归档；

  6. **前台零工程术语**：彻底清零界面上出现过的 `ctx.approval`、`STATE_DELTA`、`SHA-256`、幂等键等工程词，前台 100% 使用自然业务语言。

### 第 5 轮：视觉突围与审美拉锯战——从“50 个方框太吓人”到“暖纸白极简画布”

* **最痛苦也最关键的转折**：按规范做出第一版完整工作台后，一打开看却显得特别压抑——首页密密麻麻堆了 50 多个按钮、胶囊和小方框；更严重的是，原型里把「一面 vs 二面」做成了红橙色的对抗性「分歧警报框」。

* **业务逻辑纠偏**：你当场点破——**一面和二面根本不是打架的竞争关系，而是逐轮递进的把关关系**（一面定进不进二面，二面定进不进终审），顶多是二面带着保留意见推进，终审把各轮结论并排呈现（且严禁求平均分），绝不能渲染成“冲突警报”。

* **多轮视觉探索与减法实验**：

  * 先尝试了 Linear 风格的主从分栏、暖瓷白悬浮画布，又恢复了 6 阶段流程进度图与 3 步递进连接轨道，并大刀阔斧砍掉了约 70% 的装饰性元素，但整体还是略显零碎、分类不够工整；

  * 于是干脆并行做出两套彻底不同的视觉方向让你直接盲选对比：

    * **方向一（苹果/飞书三栏秩序网格风）**：结构工整，但你一眼看出信息卡片里多余的小字还是太多，视觉依然杂乱；

    * **方向二（对话驱动极简画布风）**：左侧暖纸白（`#F9F8F5`）对话流 + 右侧纯白（`#FFFFFF`）动态画布，列表每行只留最核心的 3 个要素，配合行悬停轻滑入动效与 6 阶段横向节点进度图——**这一版一举命中审美靶心**。

* **顺手消灭一个隐蔽 CSS Bug**：在窄屏窗口下，左侧对话栏因为缺少 `min-height: 0; overflow: hidden` 导致内容溢出形成透明遮罩，直接把右侧画布盖住点不动；当场排查定位并彻底修复。

### 第 6 轮：三层递进导航架构定型——解决“入口怎么设才不突兀”

* **核心架构命题**：锁定视觉美学后，你提出了一个决定产品上限的问题——**一级入口到底该怎么放？左侧栏和顶部栏怎么分工，才不会像传统后台一样生硬，让用户点进去自然层层递进？**

* **最终拍板的「左定空间 · 顶承视图 · 内做递进」骨架**：

  * **最左极轻空间栏（204px）**：只放真正顶层的三个业务空间——「今日待办」、「在招岗位」（下方直接挂出在招子岗，一键直达）、「人才库」；

  * **中间 `Agent` 对话栏**：可随时独立收起（快捷键 `[`），也支持通过一条平时隐形的分割线自由拖拽调整宽度；

  * **右侧上下文主画布（顶栏随空间自然变形）**：

    * 在「今日待办」：顶栏切「等你拍板 / Agent 已代办」；

    * 在「在招岗位」总览：顶栏展示各岗位 6 阶段横向漏斗全貌；

    * 点进某一个具体岗位：顶栏才自然浮现该岗位专属的「候选人漏斗 / 同池对比 / 岗位标准 V1」，彻底告别把“同池对比”突兀漂浮在一级导航上的尴尬；

    * 再点进某一位候选人：顶栏切换为清晰面包屑 + `‹ 1/N ›` 连续审阅步进器 + `★` 收藏星标，底部沉淀单人全链路信息。

### 第 7 轮：细节死磕与像素级打磨——把原型磨到像真正上线的好产品

这一轮我们围绕真实使用手感，逐个死磕了十余处细节：

* **56px 迷你图标栏与收起体验**：最左侧空间栏收起后不再直接归零消失，而是像 Gemini 一样收成 **56px 可点击的迷你图标栏**（快捷键 `\`），既能全宽沉浸看简历，又能一键切空间。过程中你眼尖抓出两个 Bug：一是品牌区写了内联 `display: flex` 导致收起后文字露在外面，二是展开/收起按钮在两处重复打架——全部当场修净。

* **左下角极简收敛**：加入隐藏的「设置」入口（外部连接 / 自动化边界 / 超时预警）后，原本的「收起对话」文字被挤变形，索性把左下角统一整理成 4 个等距纯图标，清爽利落。

* **命名克制**：把略显油腻的「Agent 随行副驾」直接简化为最干净克制的 **`Agent`**。

* **砍掉界面上的“发感谢信”复选框**：确立了一条非常核心的 Agent 产品哲学——**高频主干动作留界面，低频动作（发感谢信、生成周报等）绝不在界面上堆开关和菜单，100% 交由自然语言对话触发**。

* **把“空壳感”换成“真实业务厚度”**：

  * 6 位候选人（林致远、陈思源、赵明轩、周嘉豪、王宇凡、林佳琪）全部换上真实多段长简历全文；

  * 每个岗位的「岗位标准 V1」下方工整收纳**完整原始 JD**，既不污染日常看板，想核对原文时一滑就有；

  * 飞书妙记补上多轮真实问答与可点击的时间戳定位（如 `14:22`、`28:05`）；

  * 支持对话栏 `＋` 按钮与直接拖入 PDF 简历；

  * 支持**三合一连环自然语言指令**（如一句话同时约面 + 留追问 + 改备注），合并为一张居中确认卡一次拍板；

  * 约面内置**飞书日历空闲时段交集选择器**；

  * 支持**改期并临阵换面试官**，自动重新绑定飞书妙记采集；

  * 支持一句话给下一轮面试官留专属追问，以及一句话生成实时**本周招聘进展汇报**。

### 第 8 轮：最后一轮三向终极压测——对窗口 · 对核心链路 · 对真实极端业务环境

在把代码交给本地实现之前，我们专门做了一轮彻底的压力测试，把平时 Demo 里最容易忽略的极端情况全摆上台面过了一遍：

* **业务极端场景划清边界**：逐一讨论了 6 类真实业务极端场景，你非常清醒地划清了系统边界——

  * 候选人私下微信谈薪、口头反悔属于线下博弈，Agent 不越界介入；

  * 猎头/内推渠道撞单按“先投递时间优先”本就清晰，不做多余设计；

  * **明确需要带给后端窗口确认的两件大事**：① `Rubric V1 → V2` 升级后的历史版本隔离；② 多人并发修改同一候选人时的防冲突机制（你提出“以人为单位、但按工作和职责分离存储”的思路，记入备忘录交给后端结合乐观锁拍板）。

* **前端极端场景全量补齐护栏**：

  1. **大文件与异步解析**：PDF 简历上传走后台异步队列，顶部给轻量完成提示，**绝不强行劫持用户当前正在看的画布**；

  2. **慢调用反馈**：大模型或外部连接器慢响应时，分段流式展示进度步骤，避免假死；

  3. **同名歧义消歧**：对话里喊“林同学”命中 `林致远` 和 `林佳琪` 时，弹出点选消歧胶囊，绝不瞎猜写库；

  4. **外部连接器断连与安全重试**：模拟邮箱与飞书日历同时或单独断连的场景，清晰报错并支持**防重安全重连重试**，防止重复发信或重复建日程；

  5. **Offer 闭环完整性**：发 Offer 时若岗位 HC 已满，弹窗明确预警；同时补齐候选人 **Accept / Decline 双向回执闭环**；

  6. **高压面试与弱网稳定性**：面试官速记与对话草稿实时写入 `localStorage` 并加断网横幅提示，防断网丢稿；视口 `≤1080px`（半屏开视频面试）自动收为 56px 图标栏 + 悬浮对话抽屉；确认按钮加防连点锁态；在招岗位超过 5 个自动折叠；同池对比表锁定首列支持横向滚动；

  7. **超长简历与作品集兜底**：网站类作品集直接外链浏览器打开（不归系统包办），PDF 简历与 PDF 作品集在候选人档案里提供可缩放的「**原件 PDF / 作品集**」标签页（后续由后端接开源二进制文件阅读器统一支持图片、PDF、Word）。

### 第 9 轮：前后端彻底切分与 UI-FREEZE 锁定交付

* **彻底解耦前后端**：整理输出《前后端分工与工程增量交接清单》，明确拆清哪些是前端纯交互护栏、哪些需要后端新增接口与开源二进制文档预览流，并附上待后端拍板的架构备忘录，由你发往后端窗口。

* **立下 UI-FREEZE 最高红线**：你把定版前端代码上传仓库并交给本地编码 Agent 后，明确提出“绝不允许他动前端任何视觉上的东西，只能接入，非要动必须先向我提问”。据此沉淀出《前端接入指导书（UI-FREEZE 版）》，逐项列清 Mock 数据与真实 DSH/PostgreSQL 接口的替换映射表，并把“零视觉改动、零样式漂移、遇冲突先提问”写成铁律。

## 第五部分：设计方法论复盘——这套前端到底是怎么想出来的？

这套前端最终能做出克制、顺手、像成熟产品的质感，并不是一开始就画对了一张草图，而是在多轮拉锯里，被四个很具体的思考方法一路逼出来的：

### 1. 先不断“证伪”，用真实干活的手感把旧 SaaS 惯性全砍掉

做 B 端产品最大的陷阱，就是下意识把“数据库表翻译成菜单，把接口字段翻译成表单”。早期版本也曾掉进这个坑：首页堆满 50 多个小方框、右侧窄栏挤着填表卡片、初筛界面放着「修正第 3 项并批注」和「批量发感谢信」开关。

真正打开格局的，是连续几次**拿真实招聘动作去反问界面**：

* **“初筛看简历争分夺秒，谁有空帮 AI 改作业？”** → 砍掉“人伺候 AI”的按钮，确立“一句话下指令 → 居中只读模板卡一键确认”的交互范式。

* **“一面和二面根本不是打架，是逐轮把关！”** → 砍掉对抗性的分歧警报框，长出“逐轮递进轨道”。

* **“感谢信、周报这种低频事，干嘛在界面上占开关？”** → 逼出 Agent 产品最核心的分界线：**高频主干留界面，低频动作 100% 归自然语言对话**。

很多所谓的设计感不是“加”出来的，而是每次诚实回答“真实干活时我到底点不点？”，然后狠心砍掉 70% 多余元素之后自然露出来的。

### 2. 用“空间与动静关系”推导结构，而不是硬凑排版

两个最关键的突破都来自第一性原理推导，而不是拍脑袋选美：

* **为什么能想到“暖纸白左栏 + 纯白右画布”？**
  先想清楚了两边的本质是**一动一静**：左侧 `Agent` 对话流是随时在发生、带温度的“思考草稿纸”；右侧画布是让人沉下心看长简历、做拍板的“专注工作台”。物理角色不同，视觉材质就该拉开区分——暖纸白（`#F9F8F5`）承接对话，纯白（`#FFFFFF`）承接信息；列表不再画死板的网格边框，每行只留 3 个核心要素，靠鼠标悬停轻滑入动效给出清晰反馈。

* **为什么能想到「左定空间 · 顶承视图 · 内做递进」？**
  源于对“一级入口怎么设、侧栏与顶栏怎么分工才不突兀”的死磕：

  * **最左栏**只管最高层的“工作模式”（今日待办 / 在招岗位直挂子岗 / 人才库）；

  * **顶栏**不是固定死菜单，而是**上下文变形器**——只有点进具体岗位，才自然长出「候选人漏斗 / 同池对比 / 岗位标准 V1」；再点进单人，顶栏就退化成面包屑 + `‹ 1/N ›` 连续审阅。

  * 核心原则只有一句：**不让任何入口提前出现，用户只在需要它的那一秒看到它。**

### 3. 拒绝凭空脑补：靠“并行盲选对比”和“真内容密度”倒逼手感

* **视觉破局靠对比，不靠形容词**：空谈“极简、有呼吸感”很难落地。并行做出两套彻底不同气质的方案（秩序网格风 vs 对话极简画布风）摆在一起直接盲选，一眼就能抓出“网格小字太吵，极简画布的呼吸感和动效对了”。

* **逼出高级细节靠“灌真内容”**：只填 4 行假数据的原型往往掩盖布局硬伤。一旦把 6 份真实多段长简历、完整原始 JD、带时间戳的飞书妙记全部灌进去，真实的信息密度瞬间炸出所有空间问题——这才倒逼出了 **56px 迷你图标栏、隐形拖拽调宽线、完整 JD 藏进标准页下方、同池对比锁首列** 等真正解决空间焦虑的细节。

### 4. 最后一公里：用“反向捅刀子”把皮囊变成真产品

如果只做到顺手的主流程，它最多是个惊艳的 Demo。真正让前端立住的，是最后那一轮三向终极压测——专门对着“万一出事怎么办”去挑刺：同名怎么消歧、半屏开视频面试怎么不挤爆、断网速记丢了怎么办、PDF 解析慢怎么不抢画布、邮箱断连怎么防重发。把这些平时看不见、关键时刻能救命的轻护栏藏进极简皮囊里，产品才算真正有了厚度。

> **一句话总结可复用公式**：业务直觉不断砍伪需求 + 第一性原理拆空间层级 + 真实内容密度倒逼细节 + 极端场景反向压测。

## 第六部分：前端设计实战笔记（写给非前端背景的复用指南）

这一部分专门把本次前端打磨中真正起效的**视觉规律、布局心法、微交互原则和 CSS 工程避坑点**，用大白话沉淀下来。以后不管自己画原型，还是验收/指挥编码 Agent，都可以直接照着这份清单把关。

### 1. 色彩与材质：高级感靠“分区与留白”，不靠堆颜色和画黑框

* **用背景微差代替粗边框线**：很多后台界面显土，是因为到处画 1px 深灰框把所有卡片框死。本次界面只用了**暖纸白（`#F9F8F5`）区分左侧对话流 + 纯白（`#FFFFFF`）承接右侧专注画布**，靠极微妙的冷暖/明度差自然分区，视觉瞬间轻盈。

* **语义色极度克制**：全屏 90% 以上保持低饱和中性色（白、暖灰、深炭黑），红/黄/绿只在真正需要提醒的地方出现（超时预警、HC 满额、断连报错、当前激活节点）。颜色越少，需要用户注意的信号才越刺眼、越有效。

* **文字灰度拉出三级层次**：不要让满屏字一样黑、一样粗。把文字严格分成三档——**主信息（深黑/略粗，如候选人姓名与结论）→ 正文（深灰，如简历描述与妙记内容）→ 辅助元数据（浅灰/小一号，如时间戳、停留天数）**，一眼扫过去重点自然跳出来。

### 2. 信息密度与排版：学会“藏”和“限流”

* **列表每行严格限流（3 要素原则）**：像候选人列表、待办列表，每一行最多只放最核心的 3 个要素（例如：姓名/关键标签 + 当前阶段 + 停留时长或主动作）。其余次要信息全部收进二级详情页，绝不在列表页塞成“小字报”。

* **低频动作不占视觉面积**：发感谢信、拉周报这类低频需求，全部收进自然语言对话或二级菜单；左下角辅助图标统一做成等距纯图标，避免文字被挤变形。

* **长内容阅读护栏**：长简历、完整原始 JD、多轮飞书妙记必须留足行距、段距和留白边距，避免文字顶天立地贴着屏幕边缘塞满，长时间阅读才不压抑。

### 3. 三栏布局与屏幕适配心法（解决“内容挤爆”）

* **“固定 + 可调 + 吃满剩余”的弹性三栏**：

  * 最左导航栏：定宽 `204px`，收起后保留 `56px` 迷你图标栏（兼顾空间与一键切换）；

  * 中间 `Agent` 对话栏：允许独立收起，且中间放一条**平时隐形、悬停微亮**的拖拽线，让用户按需拉宽拉窄；

  * 右侧主画布：用弹性自适应（`flex: 1`）吃满所有剩余空间。

* **小屏/半屏降级（响应式断点）**：真实办公经常一半屏幕开视频面试、一半屏幕开系统。视口缩到 `≤1080px` 时，绝不能让三栏硬挤在一起变形，而是**自动把左栏收成 56px 图标栏、把对话栏变成悬浮抽屉**，无条件保住右侧主画布能顺畅读简历。

* **多列表格锁首列**：像「同池对比」这种列数会增长的表格，必须把第一列（对比维度/候选人名）设为吸顶锁定（`sticky`）并开启横向滚动，防止列宽被挤成一竖排单字。

### 4. 微交互与动效：丝滑而不花哨的 3 个标准

* **动效快且轻（150ms–200ms）**：列表行悬停时极轻的位移滑入和背景微亮、弹窗柔和浮现，只为了告诉用户“你指到我了、页面有回应”，绝不做拖泥带水的炫技动画。

* **防连点锁态（防重提交）**：所有发邮件、约面、发 Offer 的确认按钮，一旦点下立刻置灰锁定并提示处理中，防止手抖连点发出两封一模一样的邮件。

* **异步不打断心流**：后台解析 PDF 或慢速调用时，只在顶部给轻量进度/完成提示，**绝不强行把用户正在看的页面跳走**；需要用户做决定时才弹出居中确认卡。

### 5. 前端最容易踩的 4 个隐蔽工程雷区（验收必查）

1. **Flex 嵌套漏写 `min-height: 0` 导致页面点不动**：在 Flex 布局里，如果滚动区域的外层容器没写 `min-height: 0; overflow: hidden`，内容一长就会撑破容器，甚至在窄屏下形成看不见的透明遮罩，把旁边的按钮全挡死（这次开发中真实踩过）。

2. **HTML 内联 `style` 覆盖 CSS 折叠状态**：如果在标签上直接写死了 `style="display: flex"`，它的优先级高于 CSS 里的折叠 class，会导致侧栏收起时文字关不掉、露在外面。凡是会随交互展开/收起的显隐状态，必须全部交给 CSS 类控制。

3. **同一个面板出现两个收起/展开按钮**：侧栏收起和展开的入口全屏必须保持唯一且位置稳定，否则极易出现“点这里收起、那里按钮还在打架”的割裂感。

4. **用户输入没做本地防丢缓存**：像面试官实时速记、长段对话草稿，前端必须实时同步一份到浏览器 `localStorage` 并监测断网状态提示，绝不能一刷新或一断网就把刚写的心血清空。

### 1. 完整色彩与双主题系统（Light / Dark 全量色板）

### 5. 动效曲线与微交互节奏表（Motion Spec）

所有动效只服务于“空间变化可感知”和“操作有回声”，严格控制在 **120ms \~ 220ms** 以内：

### 第 4 层：组件质感与微交互（Components & Motion）

* **圆角外大内小，按钮全胶囊**：弹窗 `20px` → 输入框 `14px` → 内部卡片 `12px` → 行项 `8px` → 按钮与标签 `99px`；重阴影只留给真正浮在最上层的弹窗和悬浮条。
* **无框滑入 + 隐形拖拽线**：列表行平时只留极细底线，hover 染暖纸白并微扩左右内边距；拖拽调宽线平时隐形（6px 隐形热区），悬停亮起 2px 鸢尾紫，且拖拽瞬间禁用 transition 防发飘。
* **微动效快且克制（120ms–220ms）**：三栏收起用先快后慢阻尼曲线（`cubic-bezier(.2, .8, .2, 1)`），页面与气泡带 `4px` 轻浮淡入，发送按钮按压微缩 `0.95`。
* **B 端三大招牌模式**：高风险动作统一进居中毛玻璃只读确认弹窗（`blur(6px)`）；多列对比表第一列 `position: sticky` 锁定支持横向滚动；妙记时间戳折叠精华、点击就地展开。

> **直接抄给 Agent 的第 4 层话术**：
> “组件圆角按外大内小分级（弹窗 `20px`、卡片 `12px`、行项 `8px`、按钮标签 `99px` 全胶囊），只在浮层弹窗上使用重阴影。列表采用极细底线 + hover 暖底轻滑入；拖拽调宽线做成平时隐形、悬停高亮，拖拽时临时禁用 transition 保证跟手。所有微动效控制在 `150ms–220ms`；高风险操作统一用居中毛玻璃只读确认弹窗；多列表格第一列必须做 `position: sticky` 锁定支持横向滚动。”

### 第 5 层：状态驱动与防呆护栏（State & Guardrails）

* **单一数据源（State → Render）**：前端只维护一份干净的总状态账本，任何点击或自然语言指令都只改账本，再由账本统一刷新三栏视图，彻底杜绝多栏状态打架。
* **Agent 产品专属 3 道护栏**：慢调用流式吐出步骤进度；后台 PDF 解析走非阻塞顶部轻提示条，绝不强行抢切当前画布；外部接口断连清晰报错并提供防重安全重试。
* **高压办公防呆底线**：写操作确认按钮防连点锁态；长文本速记与对话草稿实时缓存 `localStorage` 并监听 `online/offline` 断网提示；高频动作配快捷键但不替代可见按钮。
* **验收必查 3 个隐蔽坑**：① 所有 Flex 滚动容器必须加 `min-height: 0; overflow: hidden` 防透明遮罩挡死点击；② 折叠/展开显隐一律交给 CSS 类，严禁 HTML 内联 `style="display: flex"` 覆盖状态；③ 同一面板的收起/展开按钮全屏保持唯一入口。

> **直接抄给 Agent 的第 5 层话术**：
> “前端采用单一状态驱动渲染，确保多栏状态强一致。针对 AI 与外部接口延迟：慢调用给流式步骤反馈，后台解析走非阻塞顶部轻提示，严禁强行跳转当前画布；外部连接失败提供清晰报错与防重安全重试。所有写操作确认按钮必须有防连点锁态；长文本输入实时缓存到 `localStorage` 并监听 `online/offline` 断网提示；所有 Flex 滚动容器必须加 `min-height: 0; overflow: hidden` 防溢出遮挡，状态显隐一律用 CSS 类而非内联 style 控制。”
