## 0. 两个必须先修的（V1 红线）

### F1 面试官 A 的速记，写进了面试官 B 的草稿（身份串写）
**现场**：面试官 A（actor 104）在第 2 轮页面输入速记 → 刷新后界面称"已持久化" → 独立查库：唯一草稿属于**面试官 B（actor 105）**、`interview_id=…802`（B 的第 2 轮）、写入时间 21:15:05。
**根因（两条都要修）**：
1. **界面没按分配范围限制编辑**：A 能看到/编辑第 2 轮（B 的场次）的速记输入框。应只有**本人被分配的场次**可编辑，其它场次只读或不可见。
2. **自动保存没有绑定"开始编辑时的场次+身份"**：切换身份/切页后，挂起的防抖仍会发出，落到新身份名下。保存请求必须带 `interview_id`，并在切换身份或离开页面前**立即 flush 或直接取消**；服务端返回 `INTERVIEWER_MISMATCH` 时不得显示"已保存"。

**验收**：A 登录 → 只能编辑自己场次；切到 B 再切回 A，A 的草稿仍在 A 名下；B 的草稿不含 A 的文字；界面提示与库一致。

**F1 的回归验收（必须自测）**：面试官 A 打开自己那场 → 输入一段速记（不点任何按钮）→ **2 秒内切到面试官 B** → 等 5 秒 → 查库：**不许出现 B 名下的这条草稿**；切回 A，A 名下草稿仍在。做不到就说明自动保存没绑定"编辑时的场次+身份"。

### F2 提交面评没有真正提交
**现场**：面试官 B 的面评表单可达，但 `scorecard` 行数全程未 +1；驱动的"PASS"只证明了"表单能打开"。
**要求**：点「提交我的独立面评」必须真的走 `scorecard/submit`；成功后人话提示并刷新为"已提交"；失败人话原因且不清草稿；提交后不可再改（按既有 revision 纪律）。
**验收**：真点一次 → `scorecard` +1（独立 psql 读回）、该行绑定本人、页面刷新后显示已提交且无编辑入口。

## 1. 九个"点不了"的入口（按剧本步骤）

| 步 | 缺什么 | 要做到 |
|---|---|---|
| S2 上传 | 没有上传入口/按钮接 `POST /intake/upload` | 拖入或 `＋` 上传 → 立即返回 task_id → 顶部轻提示轮询 → 完成后**不抢当前画布** |
| S4 初筛结论 | 没有"记录初筛结论"按钮（只有只读对照） | 通过/不通过/待定 + **确认原话** → 落库 → 刷新后可见；支持逐条人工纠偏（OV） |
| S5 选面试官 | 排期弹窗没有"选面试官"控件，日历兜底后无路可走 | 选面试官（可多选）→ 自动取空闲时段（或如实"读不到"）→ 手动填也能提交 |
| S6 改期 | 没有独立改期入口 | 改同一场（不新建），冲突时人话说明 |
| S10 终审拦截 | 没有"记录决策"按钮，看不到"还缺 X 的面评" | 决策按钮 → 缺面评时**显示缺谁**、不许提交 |
| S12 正式决策 | 同上 | 终审通过/拒绝 + 确认原话 → 唯一 current |
| S13 重复决策 | 承接 S12 | 重复提交提示"已处理过"，不产生第二条 |
| S14 NO_SHOW | 没有"标记未出席"按钮 | 选 CANDIDATE/INTERVIEWER + 原因 + 原话 → 状态变"未出席"、原因留痕 |
| S15 版本冲突 | 弹窗没有版本字段 | 提交带 `expected_record_version`（从读模型带出）；冲突时人话"这条刚被别人改过，请刷新" |
