## 2. 拆分原则：**按格式与难度分层，不按数量平均切**

按数量平切（比如 52÷5≈10 份一批）会让每批都混着 PDF/DOCX/扫描件，
一批失败时**分不清是读取路径的问题还是数据的问题**。按难度分层的好处是：
**每批只验证一件事**，失败能直接定位。

| 批 | 内容 | 份数 | 这一批验证什么 |
|---|---|---|---|
| **B1–B3** | 文本层 PDF，1–2 页 | 8 + 8 + 8 = 24 | 主路径（最快最干净）。三批重复跑同一类，验证**稳定性**与吞吐 |
| **B4** | 1–2 页 ×4 + 3–4 页 ×4 | 8 | 页数混合：长度是否影响判定 |
| **B5** | 文本层 PDF，5 页以上 | 5 | 长文档：截断、跨块归属、性能 |
| **B6** | DOCX | 7 | **另一条 reader 路径**（不是 PDF 的变体） |
| **B7** | 扫描件 / 无文本层 PDF | 2 | 质量判定 + 恢复计划（`needs_visual` / vision 补读） |
| | **合计** | **48** | |

**每批 8 份的粒度理由**：一次能看完、失败能定位、重跑成本低（真实简历单份读取 ~0.3–1s，
但结构化要模型调用，8 份是"一次跑完还能检查"的量）。
