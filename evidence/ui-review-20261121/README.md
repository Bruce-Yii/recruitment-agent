## 看得见的差异（按“数据差异 / 结构差异 / 待确认”分）

**A. 先排除数据差异（不是 UI bug）**

- 实际产品连的是预览库：1 个演示候选人、1 个岗位、人才库 1 人；原型是 6 个候选人、3 个岗位、人才库 6 人（林致远/陈思源/周嘉豪等假数据）。
- 因此姓名、岗位数、计数、面试轮次内容都不同；这些不能直接当实现差距。

**B. 结构/交互差异（需要前端窗口确认：刻意简化还是缺口）**

| # | 位置 | 实际产品 | 定稿原型 | 待确认 |
|---|---|---|---|---|
| 1 | 队列右栏顶部 | 只有“今日待办”+ 身份徽标 | “等你拍板 N / Agent 已代办 M”双状态 + “HR 推进”角色下拉 | 双状态与角色切换是否本期范围？ |
| 2 | 队列行 | 姓名/岗位/轮次 + 阶段 chip；无超时/原因 | 行内直接给“初筛 · 28h 超时”“超时 16h”“三面终审”等决策紧迫度与原因 | 行内紧迫度/原因是否缺失？ |
| 3 | 左栏岗位区 | 只有岗位列表与计数 | 岗位行带“0/2、0/1”进度 + “＋新建岗位” | 新建岗位入口是否本期做？ |
| 4 | 对话区 | 通用问候 + 两个“问题式”快捷词（今天最优先谁/待提交面评） | 个性化早报（“今天有 3 件事需要你拍板…”）+ 动作式快捷词（通过初筛/调剂/催面评） | 早报与动作式快捷词是否本期做？ |
| 5 | 候选人页头部/工具栏 | 面包屑 + 标题 + 来源/触发/连接标签 + 身份徽标；右侧星标“初筛评估” | 1/4 翻页、星标、角色页签（HR 推进/用人经理/面试官）、复制决策纪要、候选人故事头（学历/年限/推荐来源） | 翻页/角色切换/纪要复制是否本期？ |
| 6 | 候选人页信息密度 | 较紧凑，区块直给 | 更“杂志式”排版、字号更大、留白更多 | 视觉密度/字号对齐到原型还是保持现状？ |
| 7 | 整体 | 干净、偏工具化 | 更编辑化（大标题、衬线感） | 需要产品/前端定一个基准 |

**C. 不能从截图判断的**

- hover/动效、空态、错误态、窄屏（390）——本轮只截 1440 静态。
- 真实日历/邮件等外部能力（当前多为未连接，原型是假数据）。

## 请前端窗口做的事

1. 打开 `gallery.html`（或上表图片），逐条标注：**A 数据差异 / B 刻意简化 / C 实现缺口**；
2. 对 C 给出文件级对齐清单与 PR（只改 `src/app/**` / `src/client/canvas/**`，不改写链路与服务端契约）；
3. 对 B 给出“本期不做”的明确理由，产品负责人确认后再关闭；
4. 交付时同样贴 1440 截图，总控会按同一角度复拍对比。
