# 37 · 真实业务场景端到端验收剧本（真点版）

> 用途：**真人在真界面点**的验收剧本 + 判据。不是单元测试、不是接口测试。
> 场景依据（公开实践，非编造）：
> - 面评必须**在 debrief 前独立提交**，不许互相看、**不许求平均分**，决策要带理由与责任人 — Pin 面试 debrief 指南、Recruiterflow、BrightHire 结构化招聘框架、SHRM 评分量表；
> - 90%+ 的面评应在面试后 24h 内提交；少于 4/5 的 debrief 出不了明确结论说明流程坏了 — Pin / Greenhouse 口径；
> - rubric 的一档评分必须能落到**可观察的行为**，否则 debrief 无法判断 — BrightHire；
> - 候选人爽约（no-show）与改期是真实高频事件（SHRM：面试阶段 ghosting 约 41%）。
>
> 判据总表见 `docs/29`；本文件只写"这一轮按什么顺序点、每步看什么、算不算过"。

---

## 1. 场景剧本（按真实一天的工作顺序）

| 步 | 谁 | 做什么 | 关键点（现实） |
|---|---|---|---|
| S1 | HR | 打开工作台，看今天该做什么 | 一眼看清待办，不被工程信息干扰 |
| S2 | HR | 一份新简历进来（拖入或邮件），等解析 | 不阻塞界面；完成后轻提示不抢画布 |
| S3 | HR | 打开这条申请，对着岗位标准逐条看 | 每条要能点开原文；缺信息如实说"没有对应/读不出来" |
| S4 | HR | 下初筛结论（通过/不通过/待定），必须点确认 | 人的判断被记录；可对某一条人工纠偏而不覆盖 AI 原判 |
| S5 | HR | 约一面：选面试官 → 看空闲时段 → 选定 → 提交 | 空闲时段要真实；选不到可手动填，不阻塞 |
| S6 | HR | 候选人临时改期 | 改期只改同一场，不新建第二条；撞车被拒并说清 |
| S7 | 面试官 A | 进入面试官视角，看前简报 | 能看到候选人置顶约束、上一轮留下的追问、本轮重点 |
| S8 | 面试官 A | 面后写速记（中途刷新页面） | 刷新不丢；草稿落库 |
| S9 | 面试官 A | 提交自己的独立面评 | 只看到自己的；不显示别人的分数 |
| S10 | HR | 在面试官 B 未交面评时尝试终审 | **被拦**，并说清缺谁的面评（不许"少数服从多数"或平均） |
| S11 | 面试官 B | 补交面评 | 独立提交、不可改 |
| S12 | HR | 终审决策（通过/拒绝），带确认原话 | 决策唯一、可追溯；刷新后仍在 |
| S13 | HR | 同一条重复提交决策 | 不产生第二条当前决策 |
| S14 | HR | 候选人放鸽子 → 记"未出席" | 状态变 NO_SHOW、原因留痕；后续面评入口关闭 |
| S15 | HR | 两个同事同时改同一条排期 | 后提交的收到"版本冲突"，零写入，不静默覆盖 |

## 2. 每一步的验收判据（UI + 库 + 失败路径）

> 通过 = **界面上看到了** + **库里查得到** + **刷新后还在**。三者缺一不算过。

| 步 | 界面必须 | 库必须 | 反例（必须被拒） |
|---|---|---|---|
| S1 | 待办/计数可读，无工具名/SQL/哈希 | — | 显示内部 id 或错误码 → FAIL |
| S2 | 上传后立刻返回，顶部轻提示；不切换当前画布 | `intake_asset` 有行、`business_task` 有解析任务 | 阻塞界面 / 假报已入库 → FAIL |
| S3 | 每条标准：有对应/没有对应/读不出来；点开有原文 | `screening_evidence`/rubric 维度可读回 | 把"读不出来"说成"不符合" → FAIL |
| S4 | 确认后结论出现；人工纠偏只改那一条 | 决策行 + 原话哈希；AI 原判仍在 | 无原话即通过 → FAIL |
| S5 | 显示 2–3 个真实空闲时段（或如实"读不到"） | `interview` 行 + 面试官分配 | 编造时段 / 读不到却说"都有空" → FAIL |
| S6 | 改期后仍是同一场；冲突时人话说明 | 同 id、`record_version` +1、无第二条 | 新建第二条 / 静默覆盖 → FAIL |
| S7 | 简报含置顶约束、"上一轮留的"、本轮重点 | `candidate_constraint` 读得到 | 简报空白却显示"已完成" → FAIL |
| S8 | 刷新后速记还在 | `scorecard_draft` 最新行 | 刷新丢稿 → FAIL |
| S9 | 只显示本人面评 | `scorecard` 一行、绑定本人 | 看到别人的分 → FAIL |
| S10 | 明确拦截"还缺 X 的面评" | 无新决策行 | 照样通过 → FAIL |
| S11 | 补交成功、不可再改 | `scorecard` 行数 +1 | 重复提交造两行 → FAIL |
| S12 | 决策结果 + 谁拍的板 | `decision` 唯一 current、带 basis | 无原话 / 双 current → FAIL |
| S13 | 重复提交提示"已处理过" | 仍只有一条 current | 两条 current → FAIL |
| S14 | 状态"未出席" + 原因 | `interview.status='NO_SHOW'` + `interview.no_show` 事件 | 记不下来 → FAIL |
| S15 | 后提交者看到"版本冲突" | 无写入、版本不变 | 静默覆盖 → FAIL |

## 3. 必须同时覆盖的"真实极端"

1. **时间**：跨时区候选人（如 `America/New_York`）在**夏令时切换周**约面，界面显示与库内绝对时间一致；
2. **同名不同人**：两个同名候选人，Agent/界面**不许猜**，必须让人选；
3. **重复投递**：同一个人同一岗位投两次 → 复用同一条申请，不重复建档；
4. **授权失效**：邮箱/日历授权失效时，相关入口**明确报"连不上"**，不假装成功；
5. **断网恢复**：写操作中途断网，刷新后状态与库一致（不出现"界面说成功、库里没有"）。

## 4. 判定与证据要求

- 每步留 **截图 + 页面文本 + psql 读回**；三者不一致 → FAIL。
- 任何一步没法点 → **BLOCKED**（写清卡在哪、缺什么），**不许用接口结果冒充界面通过**。
- 最终产出：`PASS / FAIL / BLOCKED` 三步表 + 每条证据路径。
- 判据以 `docs/29` 为准；本剧本只是把判据串成一条真实工作流。
