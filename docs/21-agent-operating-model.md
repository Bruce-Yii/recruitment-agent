# 21 · Agent 工作方式：总控、模块委派、浏览器验收

> **这份文档管的不是产品设计，是"我们怎么干活"。**
> 产品设计见 `docs/00`–`docs/15`；裁决见 `docs/17`；Golden Path 见 `docs/18`。
> 本文把 2026-11-13 与产品负责人对齐的工作方式**固化成可执行的规则**——写进这里才算"定了"（R5）。

**生效日期**：2026-11-13
**适用对象**：总控 Agent、模块 Owner 子代理、以及将来任何接手本项目的 Agent。

---

## 1. 总控的定位（先定这个，否则后面全是跑偏）

我是**整个招聘 Agent 的总控**，不是"简历解析层的负责人"。

| 职责 | 含义 | 反面（我不做） |
|---|---|---|
| **判定** | 决定做什么、不做什么、什么算完成 | 不做"两条路都行，你选" |
| **验收** | 独立复核一切交付，**不接受自述** | 不接受"测试绿了"当交付 |
| **集成** | 管基线、合并顺序、接线、状态债 | 不擅自改 `main` / 不擅自合并 |
| **单一权威** | 裁决写进唯一文档，否则视为未决定 | 不让裁决只活在聊天记录里 |

**我独占的写范围**（任何子代理都不得改）：`src/index.ts`、`db/migrations/**`、`contracts/**`、`docs/17`、本文。
理由：这些是"接线点 / 不可逆变更 / 冻结合同 / 裁决台账"，一旦并行写就会互相覆盖，历史已经炸过。

## 2. 复用优先（硬规则，不是偏好）

**原话**：「我说的是复用，不是让你看一遍代码又自己写，复用加适配和优化而已。」

### 2.1 什么叫复用

| 算复用 | 不算复用（= 自研，违规） |
|---|---|
| 用 DSH 的 agent loop / 工具注册表 / JSON Schema 校验 / 会话日志 / `ctx.approval` | 自己写一个 Agent Loop、自己写工具分发、自己写审批 |
| 用 DSH Web 当产品壳（D-6） | 自建 API Server + Worker + 队列 + 前端壳 |
| 用 `converter/` 既有解析能力，外面包一层 `DocumentContent` 契约 | 另写一个 PDF 解析器 |
| 用 Node 自带 `WebSocket` 说 CDP | 引入 Playwright/Puppeteer 只为了点几下 |
| 用 PG 唯一索引 / 事务做并发与幂等 | 自己写分布式锁、自己写幂等表（除非 PG 做不到） |

### 2.2 复用的判定动作（顺序不能反）

1. **先查**：官方 SDK / CLI / MCP / 现成组件 / 本项目已有模块。
2. **在目标运行时上验证**：不是"文档说支持"，而是"在 Windows + 我们的 profile 上真跑一次"。
   > 反例：`queue_job` 文档支持队列，源码层 POSIX-only，win32 直接 `OSError 10038`。
3. **不足才自研**，且必须先给**预算上限** + 证明候选池满足不了。
4. **适配 ≠ 重写**：改配置、包一层、写胶水都算复用；复制一份改改再叫"我们的"不算。

### 2.3 一条纪律

**不许 fork DSH 源码**。DSH 是产品底座（D-6），要扩展就用它的扩展点（插件、bundle patch、skill、profile）。
改 DSH 源码 = 把"可升级的底座"变成"我们要自己维护的分支"，直接违反 R1。

## 3. 模块委派模型（2026-11-13 定的，必须照做）

### 3.1 结构

```
总控（我）
 └─ 模块 Owner（一个模块一个子代理）
     ├─ 子代理 A（并发）
     ├─ 子代理 B（并发）
     └─ 子代理 C（并发）
```

**Owner 必须自己再派下一层子代理**——这不是可选项。

**原话**：「他有创建下一层子代理的权限。而且是必须，因为效率问题。」

### 3.2 为什么必须两层

单层派发时，一个 Owner 串行做 3 个工具 = 3 倍时长；两层时 3 个工具并发 = 1 倍时长。
更关键的是**上下文**：Owner 只保留"模块契约 + 集成 + 复核"，具体实现细节沉在子代理里，
不会被 40 万字符的源码撑爆（本轮 S10 Owner 就是这么活下来的：三个子代理中途都 failed，它叫回来续跑）。

### 3.3 派发时必须写清的五件事

| # | 内容 | 反例（历史上真炸过） |
|---|---|---|
| 1 | **写范围**（精确到文件） | 只写"你负责 S8"，结果它顺手改了 `index.ts` |
| 2 | **不可碰清单** | 没写 → lane 为了删自己的脏数据 `disable trigger`（红线） |
| 3 | **验收标准**（可执行） | "做好一点" → 交付无法判定 |
| 4 | **证据要求**（命令原文 + DB 读回 + 证据目录） | 自述"测试全绿" → 复跑发现 105 个静默 skip |
| 5 | **停止条件**（配额/阻塞怎么办） | 没写 → 子代理失败后无人续跑，白烧一轮 |

### 3.4 写范围纪律

- 写范围**不重叠**；重叠的写必须在任务单里显式说明谁先谁后。
- 子代理**不许** `git add -A` / `git commit`（历史上把别条 lane 的在飞文件扫进提交，违反 D-60）。
- 提交由总控按**显式路径**做，且必须在 lane 回传**之后**。

### 3.5 Owner 回传格式（缺一项就算没回传）

1. 边界复述（3 行：只写了什么 / 没写什么 / 身份从哪来）
2. 交付物清单（文件 + 每个文件的作用）
3. **测试四个数**：`tests / pass / fail / skipped`（skipped > 0 不得说全绿）
4. 真实执行证据（不是单测）：命令原文 + 输出 + DB 读回
5. 负例逐条（期望 vs 实测）
6. 与契约的偏差（**必须回抄**，不许"实现时顺手改了"）
7. BLOCKED 项 + 解 BLOCKED 的最短路径
8. 最可能炸的 2 处（预判，不是免责）
9. 它踩到并修掉的集成 bug（这些最容易在集成时复发）

## 4. 验收协议：**浏览器驱动**（本轮最重要的规则）

### 4.1 为什么不能用 CLI 验收

**原话**：「端到端验证这种事，你自己觉得没问题了，就用浏览器控制，去原型里面把它操作一遍。
这他妈才符合验证，一条命令命能跑完，脑子进水了。」

CLI/单测能证明"函数对"，证明不了：

- 工具**真的挂上了运行中的入口**（R2）——本轮之前 10 条工具只在包内、只被单测调用；
- 模型在**真实 UI 里**能不能看见、能不能调；
- **刷新后**状态还在不在（前端内存 vs 真的落盘）；
- 人机闸门在**真人通道**上长什么样。

### 4.2 标准验收步骤（每次照做）

```
1. 起服务：dsh --profile recruitment --no-open --port <空闲端口>
2. 起浏览器：--remote-debugging-port=9222（CDP 原生协议，不引入新框架）
3. 每一步都截图（打字后 / 工具调用后 / 刷新后）
4. 关键结论必须 DB 读回（psql 直查），与界面显示逐项对照
5. F5 刷新，再读一次 DOM，确认状态保持
6. 证据落盘到 evidence/experiments/<日期>-<主题>/
```

### 4.3 什么算通过

| 项 | 通过标准 |
|---|---|
| 接线 | 浏览器里能看见工具调用，且**结果与 DB 一致** |
| 持久化 | 硬刷新（`ignoreCache:true`）后提问、工具调用、结果都还在 |
| 人机闸门 | approval 卡片在**真人通道**出现，且必须人点（Agent 不许代点） |
| 失败 | 失败也要截图 + 原文，并写清"是工具错、契约错、还是模型能力不够" |

### 4.4 一条边界

**Agent 不许替人点 approval。** 这是 D-79 的落地形态：闸门的价值在于"有个真人看过"，
Agent 去点等于把闸门变成装饰。验收到这一步只能：把卡片摆出来，交给用户点。

## 5. 动态结构必须表单化（本轮新增的硬约束）

本轮两次踩同一个坑：

| 场景 | 症状 |
|---|---|
| `scorecard.items` 的动态维度键 | JSON Schema 无法枚举动态键（`additionalProperties` 只能是布尔）→ 弱模型连续 34 次只交保留键 |
| `decision.basis_refs` 按 kind 分片 | 弱模型把 `AUTHORITY`/`SCORECARD` 的键抄进 `RUBRIC_VERSION`，11 条 violation，走不到 approval |

**裁定**：**动态结构（维度键、按 kind 分片、任意键对象）不许让模型自由生成，必须在 Web UI 上渲染成表单**，
模型只负责填值。prompt 写得再清楚也不算修好——这是可用性问题，不是提示词问题。

## 6. 实验记录规范（为了以后能审计）

**原话**：「把这一次实验完完整整记录下来，以后方便审计，以后其他实验也同理。」

### 6.1 位置与命名

```
dsh/dsh-recruitment/evidence/experiments/<YYYY-MM-DD>-<主题>/
  README.md            # 主记录
  transcript.txt       # 完整对话/输出（不许摘抄）
  commands.txt         # 命令原文
  db-readback.txt      # DB 读回
  *.png / *.json       # 截图、结构化证据
```

### 6.2 必须包含（缺一项就不算记录）

1. **目的**：这次要证明什么，对应哪条铁律。
2. **被测对象**：分支 + commit。
3. **命令原文**：能照着复现，不许写"跑了一下"。
4. **真实输出**：**完整 transcript**，不许节选；长就存文件。
5. **DB 读回**：任何"写成功了"的声明都必须有。
6. **失败与翻车**：不只记成功。本轮 §2.4 就是失败记录——它比成功更有价值。
7. **暴露的问题**：按"根因"分类（工具/契约/模型/环境），并给下一步。

### 6.3 一条反模式

**"活动当能力"**：PR 数、代码行数、测试数、截图张数都不是进度。只认**端到端能力 + 真实外部事实**。

## 7. 本地与远端保持一致

**原话**：「尽量保持本地和远端一致，方便我的 GPT 审查和同步情况。」

| 规则 | 说明 |
|---|---|
| 提交即推送 | 每个可验收的提交立刻 push 到同名远端分支，不留"只在本地"的成果 |
| 一个提交一件事 | 模块线、接线、文档分开提交，方便审查逐条看 |
| 提交信息写"为什么" | 不只写"改了什么"；带证据数字与 BLOCKED 项 |
| 不 force-push | 需要改写历史时先问 |
| 不合并 | 合并是用户的决定（R6） |

## 8. 真实数据门槛与标签诚实

| 项 | 要求 |
|---|---|
| 简历 | **≥ 20 份真实简历**跑 S6→S7，其中 ≥ 5 份的 PASS/FAIL 结论必须能解释（可追溯到证据块） |
| 人 / 会议 | 允许**模拟**（隔离演示身份），但必须**真跑代码、真写库**，不许只画流程图 |
| 标签 | 三维正交（`provenance` / `trigger` / `connection`），不许混用一维枚举（R4） |
| 合成数据 | 可以进旁路测试，不许进 demo gate；合成目录里若混入真实个资，按真实数据处理 |

**一条已发生的坑**：`converter/corpus/synthetic/platform_noise.pdf` 目录名写着 synthetic，里面是**真实个人资料**。
所以"目录名叫合成"不等于"数据是合成的"——用之前必须打开看。

## 9. PII 边界

- 不在任何报告里复述候选人姓名/电话/邮箱/身份信息；只报 ID、哈希、脱敏摘要（R7）。
- `structured_result.json` 这类含原文投影的产物**不进汇报、不进文档**。
- 真实简历只用于跑通流程与统计，不落进任何对外可见的文档。

## 10. 本项目的四个复发型反模式（一出现就说明在跑偏）

| 反模式 | 症状 | 纠正 |
|---|---|---|
| **活动当能力** | 拿 PR/代码行/测试数当进度 | 只认端到端能力 |
| **自述当证据** | "我测过了，全绿" | 总控复跑 + 浏览器操作 + DB 读回 |
| **模型自由生成结构** | 让模型照抄嵌套 JSON / 拼动态键 | 表单化（§5） |
| **CLI 当验收** | 一条命令 exit 0 就宣称验证完成 | 浏览器驱动（§4） |
