# 12 · 分层验收：可检验 / 可观测 / 模型兜底 / 人工兜底 / 系统治理

**日期**：2026-11-12
**前置**：`11-pdf-acceptance-criteria.md`（转换器本身的验收）
**适用**：转换器从"工具"变成"Agent 工具"之后的四层机制

---

## 0. 核心原则

> **每层的验收 = 注入一个已知失败，验证它在哪一层被发现、以什么形态被发现、能不能被上一层接住。**

正常路径测不出兜底。**只有故障注入能。**

反面（必须避免）：
- 跑一批正常 PDF，全过了，宣布"兜底机制可用"——这只能证明主路径能跑
- 只验证"失败了会打日志"——日志不是可观测
- 只验证"会进队列"——不验证"队列里的东西真的挡住了下游"

---

## 1. 五层顺序与各自要回答的问题

| 层 | 回答的问题 | 属于 |
|---|---|---|
| ① 可检验 | 工具知道自己错了吗？ | **工具层** |
| ② 可观测 | 不靠日志能查吗？ | **工具层** |
| ③ 模型兜底 | Agent 会换招吗？ | **工具→Agent 层** |
| ④ 人工兜底 | 人接得住吗？ | **系统层** |
| ⑤ 系统治理 | 账平吗？ | **系统层** |

顺序不可颠倒：①的输出是③的输入；②的数据是⑤的输入。

---

## 2. 各层验收标准

### ① 可检验（工具自检）

**验收问题**：工具能不能自己判自己不合格？

**注入样本（必须全部构造）**

| 编号 | 注入的缺陷 | 期望行为 |
|---|---|---|
| INJ-01 | 输出正文改 1 个字符 | 保真 `Counter` 不等 → FAIL |
| INJ-02 | 输出少 1 页 | 页覆盖不等 → FAIL |
| INJ-03 | 塞入一个凭空 URI | 链接校验 → FAIL |
| INJ-04 | 图像页标成 `complete` | 红线 → FAIL |
| INJ-05 | `unreadable` 标成 `absent` | 三态校验 → FAIL |
| INJ-06 | 正文含 `\ufffd` / `(cid:N)` | 坏字形 → FAIL |
| INJ-07 | 正常文件（对照组） | PASS，**不得误报** |

**通过判据**
- 6 条红线注入样本：**拦截率 100%**
- 对照组：**误报率 0**
- 每条 FAIL 必须带 `code` + `location`，不能只说 "failed"

---

### ② 可观测（每次调用留痕）

**验收问题**：把日志关掉，还能查到这次调用发生了什么吗？

**注入样本**

| 编号 | 注入 | 期望 |
|---|---|---|
| OBS-01 | 关闭应用日志后跑 10 份 | 仍有 10 条记录 |
| OBS-02 | 同一文件跑两次 | 两条记录，`source_sha256` 相同、`run_id` 不同 |
| OBS-03 | 强制读取器崩溃 | 有记录，`status=CRASHED`，不是"没有这条" |
| OBS-04 | 查询四维：code / 来源 / 时间 / 状态 | 四个维度都能查到同一批记录 |

**通过判据**
- 记录覆盖率：`调用次数 == 记录条数`（100%）
- 字段完整率：`source_sha256` / `converter_version` / `status` / `issues` / `elapsed_ms` 全部非空（100%）
- **日志关闭后仍可查**（这是本层的核心判据）

---

### ③ 模型兜底（Agent 换招）

**验收问题**：给 Agent 一个失败，它会不会**换一个办法**，而不是重复同一招？

**对照实验设计**

| 组 | 给 Agent 的信息 | 期望 |
|---|---|---|
| A 组（对照） | 只给 `{"error": "failed"}` | 成功率低 / 只能重试同一招 |
| B 组（实验） | 给结构化 issues：`{code, location, suggested_action, retryable}` | 能选出不同动作，成功率显著更高 |

**通过判据**
- B 组兜底成功率 **显著高于** A 组（给出具体数字，不能只说"更好"）
- **无效重试率**（同一文件同一动作重复次数 / 总尝试次数）≤ 阈值
- 每次兜底尝试必须被记录：试了什么动作、结果如何
- **必须用真实 Agent 跑**，不能 mock（这是行为验收，不是代码验收）

**注意**：如果 B 组并不比 A 组好，说明 **issues 不够可操作**——要回去改 ① 的输出契约，而不是放宽 ③ 的标准。

---

### ④ 人工兜底（队列）

**验收问题**：该进队列的进了吗？**没处理的真的挡住了吗？**

**注入样本**

| 编号 | 注入 | 期望 |
|---|---|---|
| HUM-01 | 纯图像页（模型也搞不定） | 入队，状态 QUEUED，有 deadline |
| HUM-02 | 队列项未处理 + 该候选人参与筛选 | 筛选结论显示"待核"，**不得显示"不符合"** |
| HUM-03 | 构造"若放行就会错误淘汰"的场景 | 必须被阻断 |
| HUM-04 | 队列项超 24h | 触发升级 |
| HUM-05 | 人工补正后 | 机器结果与人工结果**两份都保留**，不覆盖 |

**通过判据**
- 该入队的 **入队率 100%**
- 未处理项的 **阻断率 100%**（这是本层核心判据，比入队更重要）
- 每次状态变更都有审计（谁/何时/为什么）
- `deadline` 必须存在且被检查

---

### ⑤ 系统治理（批量）

**验收问题**：账平吗？会不会无限重试？告警会响吗？

**注入样本**

| 编号 | 注入 | 期望 |
|---|---|---|
| SYS-01 | 批量跑全部语料 | `输入 = ACCEPTED + 队列中 + 已拒绝`，**误差 0** |
| SYS-02 | 持续失败样本 | 重试 ≤3 次后停止，进队列 |
| SYS-03 | 积压超 24h | 告警触发 |
| SYS-04 | 同一 code 1h 内超阈值 | 告警触发 |
| SYS-05 | RED_LINE 命中 | 立即告警 |
| SYS-06 | 对任一失败记录重放 | 重跑成功，结果写回同一条，历史 attempts 保留 |

**通过判据**
- **账平误差 = 0**（最关键）
- 重试次数 ≤ 上限（无无限重试）
- 三种告警（积压/突增/红线）全部能触发
- 可重放且不覆盖历史

## 3. 故障注入矩阵（总表）

行 = 故障，列 = 应由哪一层接住。每格都要有注入样本 + 实际输出。

| 注入的故障 | ① 自检 | ② 记录 | ③ 模型 | ④ 人工 | ⑤ 治理 |
|---|---|---|---|---|---|
| INJ-01 改 1 字符 | 必须 FAIL | 记录 | — | — | — |
| INJ-02 少 1 页 | 必须 FAIL | 记录 | — | — | — |
| INJ-03 假 URI | 必须 FAIL | 记录 | — | — | — |
| INJ-04 图像页标 complete | 必须 FAIL | 记录 | — | — | — |
| INJ-05 三态混用 | 必须 FAIL | 记录 | — | — | — |
| INJ-06 坏字形 | 必须 FAIL | 记录 | — | — | — |
| 加密 PDF | 报 code | 记录 | — | 入队 | — |
| 纯图像页 | `needs_visual` | 记录 | 换招 | 模型失败后入队 | — |
| 持续超时 | `reader_timeout` | 记录 | 重试 1 次 | 到顶入队 | ≤3 次后停 |
| 读取器崩溃 | `CRASHED` | **必须记录** | — | 入队 | 计入失败率 |
| 日志被删 | — | **仍可查** | — | — | — |
| 整批跑 | — | 全记录 | — | 该进都进 | **账平** |

---

## 4. 每层的证据要求（对齐 E1–E4）

| 层 | 必须给出 |
|---|---|
| ① | 注入样本文件路径 + 运行命令 + 真实输出（FAIL 的 code 与 location） |
| ② | 关日志前后的查询结果对比 + 记录条数 == 调用次数 |
| ③ | 对照实验的原始数据（A/B 两组各自的成功/失败清单），**不是结论** |
| ④ | 入队清单 + 阻断验证（下游查询的实际返回） |
| ⑤ | 账平计算的四个数字 + 告警触发的实际记录 |

**禁止**：
- 只给"通过了"三个字
- 用正常样本冒充故障注入
- 用 mock 冒充真实 Agent（第③层）
- `skipped > 0` 却宣称全绿

---

## 5. 三个反直觉但重要的点

**① ③ 层是行为验收，不是代码验收。**
要证明"Agent 看了 issues 会换招"，必须真实跑。代码里有分支不算。

**② ② 层要"把日志关掉"验。**
有日志谁都能有；关掉日志还能查到才叫可观测。

**③ ④ 层必须验"阻断"，不只是验"入队"。**
入队容易；挡住下游难。要构造"若放行就会错误淘汰候选人"的场景——这是唯一能证明阻断有效的办法。

---

## 6. 一条总不变量

> **账要平**：`输入总数 = ACCEPTED + 队列中 + 已拒绝`

任何一份文件都不能"消失"。这是五层全部完成后的最终检验，
也是"不怕失败、怕失败没被发现"的数学表达。
