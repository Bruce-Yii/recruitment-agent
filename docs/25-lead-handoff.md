## 1. 先看一个完整场景（比十条原则有用）

**背景**：岗位「后端工程师（演示）」`DEMO-BE-001`，岗位标准 3 条——`work_exists`（有工作经历，权重 0.5）、`edu_exists`（有教育经历，0.25）、`team_lead`（有 ≥1 年、≥3 人带团队经历，判断型，0.25）。

**① 简历进来（S6）**
一份 RTF 简历上传 → 系统嗅探出真实类型（不看扩展名）→ 建候选人、建申请、存材料、解析出结构化字段（姓名/电话/邮箱/工作经历/教育经历）并**给出每条字段的状态**：`present / absent / unreadable`。
关键：**收到什么就是什么**。系统**不**判断"材料齐不齐"、**不**要求补件、**不**让人补录它没读出来的字段。

**② HR 打开工作台（今天的活）**
他看到"我的待办"：待初筛 1、我的面试、逾期面评、待审批、连接器异常、等待人工的任务。
他点开张三这条申请：左边是**结构化材料**（每条带"第几页第几行 + 原句"），右边是**对着岗位标准的标注**（这条经历对上哪一条要求、满足/不满足/没信息）。

**③ 初筛（S7）**
Agent 在**已收到的材料**里逐条对着岗位标准找证据，产出三态（有证据/没有证据/读不出来）+ 一句**建议**并标"需要人确认"。
它**不**替人下结论。人拍板后，走一次 `record_human_decision`：
- "通过" → 申请自动进 S7（面试阶段），状态 ACTIVE；
- "不通过" → 决策落库 + 申请**自动结束**（`CLOSED`），工作台不再给它"去安排面试"。
全程一个事务，重复点只会回"已经决定过了"。

**④ 约一面（S8）**
Agent 依据全公司招聘事实 + 日程空余给**建议时间**（不在系统里拉人开会协调）。
面试官打开这场面试，看到：材料、岗位标准、**这一轮可以参考的 3–4 条要点及理由**（参考不是指令，怎么问是面试官的职权，HR 不介入）。

**⑤ 一面结束（S9）**
飞书转写自动进来 → 入库 → 拆解：聊了哪些主题、对应岗位标准哪几条、哪几条没覆盖。
面试官独立提交面评（自己那份，别人看不到）。

**⑥ 二面面试官打开面试**
多一层：**紧邻上一轮实际发生了什么**——按岗位标准维度：`work_exists` MET/4 分、`team_lead` NOT_MET/2 分、`edu_exists` **上一轮没覆盖**（原因：上一轮没给这一维评价）。
于是本轮参考里有一条："上一轮没覆盖「教育经历」，岗位标准里有这条（权重 0.25），这一轮可以自己确认一下。"

**⑦ 决策（S10）**
两位面试官的面评独立汇总（不互相影响、缺一份就等，不伪造），Agent 汇总证据与分歧但**不产结论**；**人**做决定并留痕：谁、何时、依据哪份材料、哪版标准、哪几条面评。
半年后有人问"这个人当时为什么没过"，读得出全链。

**这就是产品的全部价值**：把散落的上下文按人串起来、变成人能快速看懂的东西、判断权留在人手里。

## 2. 产品为什么这么设计（原则 → 推论）

| 原则 | 为什么 | 推论（别做相反的事） |
|---|---|---|
| **以"人"为单位存上下文** | 真实痛点是上下文散落（简历/面试官脑子/飞书/Excel），不是缺系统 | 阶段只是业务标签，不是模块清单；**不需要**"人才沉淀"独立模块 |
| **Agent 只做辅助** | 招聘涉及对人的判断，责任在人 | 不替人初筛下结论、不替人决策、不替面试官打分 |
| **人的判断必须留痕** | 要追责 | 真人、真界面、写库、可读回（谁/何时/依据/版本） |
| **外部世界只"接进来"** | 企业系统千差万别，我们不知道客户用什么 | 只定通用连接器契约；**不在系统内做沟通协调**（不拉会、不催办） |
| **流程是线性的** | 一面依赖初筛、二面依赖一面 | 不做多面试官联合会审、不把"分歧"当常规场景 |
| **复用优先** | 底座是 DSH（会话/子代理/任务面板/计量/skill/preset）+ PG | 自研队列/Runtime/解析/UI 框架 = 违规，不是勤快 |
| **五事实分离** | 业务/事件/任务/执行/副作用各有真相 | Agent 不拥有不变量；长任务必须跨会话可恢复；外部副作用必须有回执 |
| **证据按"可复核"不按"坐标"** | 有的材料没有坐标（RTF/纯文本） | 源哈希一致 + 定位唯一 + 原句逐字命中；缺 bbox 不是拒绝理由（D-110） |

**三句话口径**：收到什么就是什么 · 流程线性 · 参考不是指令。

## 3. 判断框架（你要带来的真本事）

**任何问题按三层答**：① 业务（谁做？是他的职权吗）→ ② 产品（用户会感觉到什么变化）→ ③ 工程（怎么实现、怎么证明）。

**设计任何流程前先答四问**：谁做？是他的职权吗？谁受益？会不会要求人越出角色？答不上来 → 不许写进产品流程。

**真问题 vs 伪需求**

| 真问题（要做） | 伪需求（别做） |
|---|---|
| 决定"通过"还要再点一次推阶段 | 退回补充材料状态机（简历就一份） |
| 决定"不通过"还挂在"在办"、还被提示"去安排面试" | 让 HR 定面试官该问什么 |
| 材料只能引用字段、核不到原文 | 多面试官联合会审 / 分歧仲裁 |
| 面试官不知道上一轮问了什么 | 独立人才沉淀模块 |
| 按岗位名/候选人名找不到 | 主动捞人 sourcing |
| 系统内部编号被念给 HR | 角色×视图矩阵 |
| 约面试要人肉对时间、看不到空余 | 在系统里做沟通协调 |

## 5. 我踩过的判断类错误（带当时的原话，别重犯）

1. **用"能实现"代替"真实业务谁负责"**。我提过：让 HR 给面试官定重点（"数据库别深问"）、多面试官看法不一致要仲裁、材料不全就退回补充、面试时间在系统里协调。产品负责人的反应是："真实业务场景里哪有这种傻逼事情""你这不招笑吗""面试官想问他跟 HR 什么关系"。
   → **他的判断依据是"谁有这个职权"，不是"能不能实现"。**
2. **把线性流程写成并行会审**。"一面依赖初筛、二面依赖一面"，我却说"几个面试官看法不一致"。
3. **把工程正确性当产品进度**。我花大量时间在追溯环、机检、测试数上；他说："这种东西永远是我们项目的最低标准""任何一个 AI 窗口都能解决代码红绿的问题"。
   → **汇报先说"用户会感觉到什么"，看不到变化的改动优先级最低。**
4. **在开发环境拿"交付质量"当理由**。我用"HR 体验会变差"反对在本地开发用免费模型，被骂"我们还在验证呢，影响你妈 HR 啊"。
   → **先分清阶段**：现在是本地开发/验证，用 HY4；交付口径另议。
5. **把"缺口"做成焦虑清单**。我给面试官列"这块没问那块没问"，他说"这很傻逼""不能钻牛角尖"。
   → 只列**岗位标准内**的维度，用事实陈述（"这一维本轮未涉及"）。
6. **用表格和清单替代判断**。我列了超长缺口清单，他回："你他妈给我列了一个超长的清单，这让我太无语了。"
   → **要判断，不要罗列**；一次最多 3 件事，说清为什么。
7. **替他做决定**。产品语义变更必须写成裁决（我裁过一条：REJECT = 申请结束，入了台账 D-142）。
8. **声称"已派/已完成"而实际没派**（诚信红线）。先调工具，再写"已派"；进度必须给得出产物路径或 agent 名。
9. **"不做清单"写太死**。正确是"**不主动提**"：不主动扩范围、不塞进验收；明确要求时可做，但要先说代价 + 立裁决。

## 7. 怎么"廉价核实一件事"（比跑全量有用）

不要信 lane 的自述，也不要靠跑全量。**针对这一件事**造一条最短证据链：

1. **读工具/接口** → 直接调它（真库、只读事务），看**返回的真人话文本**，不是看它是否 200。
2. **写业务** → 调完之后用**独立 psql** 读回那一行（谁/何时/什么状态/版本），并对比调用前的行数。
3. **界面** → 真 Host + 真浏览器（CDP），截 1440 与 390，把 body 文本落盘，机检"该出现的出现、该消失的消失（机器码/UUID/缺件话术）"。
4. **Agent 行为** → 真会话跑一次，解码 `session.v4.jsonl.zstd`，数工具调用矩阵 + 把 assistant 原文抄出来读（看它像不像招聘助手、有没有反向免责）。
5. **失败路径** → 一定造负例：未授权/歧义/哈希不符/缺前置，证明 fail-closed 且**零写入**。
