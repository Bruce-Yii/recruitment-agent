## 1. 一句话定位

**我们是跑在 DSH 上的「招聘 Agent」：以「人」为单位把散落的上下文串起来，用 Agent 的分析能力把它结构化、标注、给出建议，把人的决策留给人类闸门。不是招聘平台，不是人事系统，不是沟通工具。**

三条底线（不可让步）：

1. **Agent 是辅助，不是替代。** 它不替人做初筛结论、不替人做决策、不代面试官打分。
2. **AI 有毛病，必须用提示词/工作流管住。** 目标不是"限制它"，是把它的正面放大、负面压到最低。
3. **不越界。** 不主动接管别人的事：企业人事系统的具体对接、Offer 与入职、主动捞人（sourcing）由别人负责或不在当前范围；我们**不主动提、不主动扩**。你或客户明确要求时才做，且先写清代价与边界（见 §4）。

## 2. 我们靠什么成立（五件套）

| 层 | 内容 | 边界 |
|---|---|---|
| **单位** | **人**（候选人 / 一次申请）：简历、面试、面评、决策、每一轮结果都挂在这一个人身上 | 不按"模块/阶段"组织数据；阶段只是业务标签 |
| **上下文** | 岗位与 JD、rubric（评分标准，可版本化）、候选人材料、面试与转写、面评、历史决策、企业侧信息 | 企业侧信息属**外部**，我们只接收 |
| **Agent** | DSH 会话 + 工具：读上下文 → 分析 → 结构化 → 标注 → 建议 | 不拥有业务不变量；不绕过闸门 |
| **连接器** | 把外部世界接进来：投递/邮件、飞书（日程/会议/转写）、企业人事系统、公开信息 | 只定义**通用契约**，不实现具体客户对接 |
| **人的闸门** | 批准评分标准、提交面评、做出决策、确认人的判断 | 真实人操作，可追责 |

**DSH 已经有的，我们只做"接上 + 展示"**：会话、子代理、Agent 团队协作、共享任务面板、token/缓存/上下文/额度计量、任务进度。**不自研、不重复实现。**

## 3. 我们做什么（v1.0 的实质）

一条纵向切片：**简历进来 → 读得懂 → 人看得明白 → 面得下去 → 评得出来 → 人做决定 → 事后查得到**。

- **S6 接收**：收到什么就是什么，收到的就是**全部事实依据**（不索要材料、不判定"缺件"、不要求人补录系统没读出来的字段）。
- **S7 初筛辅助**：只在已收到的材料里逐条对照，产出**有对应 / 没有对应 / 读不出来** 三态；并给**一句倾向性建议**、显式标明"**这是建议，不是决定**"（默认行为已定 = B，见 `docs/17` D-144；用词见 §6.4）。
- **S8 面试安排**：Agent 依据全公司招聘事实 + 日程空余给**建议时间**；不在系统里拉人开会协调。
- **给这一轮面试官的参考（不是"HR 定重点"）**：Agent 依据岗位标准、候选人材料、**前面轮次实际发生了什么**，给**当前这一轮的面试官**一份参考——"这一场可以重点了解哪几点、每点为什么值得问"。**这是参考不是指令**：怎么问、问多深，是面试官自己的职权；**招聘者不介入制定面试问题**（流程上不存在这个环节）。
- **流程是线性的**：一面依赖初筛、二面依赖一面，逐轮推进；**不做多面试官联合会审**，也不把"几个面试官看法不一致"当成常规场景（真实情况是各自承担自己那一轮）。
- **前置轮次摘要（给下一轮面试官的）**：结构化列出事实——哪些主题聊了、回答与评价如何、**岗位标准里哪些维度本轮确实没覆盖**。**只列岗位标准内的维度**，不罗列临时想到的鸡毛蒜皮（"哪块没问"不能变成焦虑清单）。
- **S9 转写与面试记录**：线上从会议系统接，线下"点一下开始录音"，转写复用成熟软件；标签必须诚实。
- **S10 评价与决策**：面试官独立交面评；Agent 汇总面评与分歧（不产结论）；**人**做决定并留痕。
- **展示**：HR 打开工作台能看到"今天要干什么、卡在哪、这个人到哪一步"；材料**不以 PDF 原文为主视图**，而是结构化 + 对照岗位标注 + **旁边可点开原文**。
- **可追溯**：半年后问"这个人当时为什么没过"，读得出：简历 → 初筛依据 → 面评 → 谁拍的板、什么时候。

## 4. 不主动提（不主动扩范围）

> **这些不是"永远不做"，而是"我们不主动提、不主动开"**：不主动往这些方向扩需求、不主动把它们塞进 v1.0 的验收。
> 你或真实客户**明确要求**时可以做，但必须先做两件事：① 说清代价（工期 / 复杂度 / 需要什么外部条件）；
> ② 在 `docs/17` 写一条裁决。**禁止**的是"我们自己觉得应该做，然后偷偷加进来"。

| 不主动提 | 为什么不主动提（不是不能做） |
|---|---|
| **主动找人 / sourcing / 人才挖掘** | 边际价值低：企业通常有猎头、有 BOSS 直聘、有官网投递。我们的主体职责是**把投递接好、用好**；要做也可以接公开信息搜索，但由客户提出再做 |
| **Offer 与入职交接** | 属企业人事系统；我们不知道客户用什么系统。客户要求时才按通用契约接。**注意（D-155.1）**：这里不主动提的是 **Offer / 入职"系统"**；**发一封 Offer 邮件 / 通知邮件属基础邮件能力**，见 `docs/31` |
| **企业人事系统的具体对接实现** | 没有真实客户环境；先只定义通用连接器契约（§5），具体项目来了再对 |
| **在系统内做沟通/协调**（拉人开会、站内消息催办） | 沟通在系统外发生，我们记录结果更划算；客户明确要"站内催办"时另议 |
| **"人才沉淀/复盘"独立模块** | 我们本来就以人为单位存上下文，数据已在；除非客户要专门的运营视图，才做 |
| **角色 × 视图矩阵** | 优先按"这一轮需要什么上下文"给；客户要固定角色页面时再加 |
| **把 CI 当验收标准** | 代码红绿只说明能不能跑，不说明产品对不对；这条不建议改 |
| **把 12 阶段当模块清单 / 覆盖率指标** | 阶段是业务标签，不是模块清单；不要用它算进度 |
| **多租户 / 企业级部署 / 云端存储 / 权限体系 / 合规留存** | 属企业版部署范畴；客户私有化或云化时再做 |
| **自研队列 / Runtime / 解析 / UI 框架** | DSH 与成熟软件已有（R1 复用铁律）；只有证明现成方案不满足时才考虑 |

## 5. 连接器：只定义契约，不实现对接

通用形状（占位，具体字段待设计）：

```
连接器 = 读：能拉取某类外部事实（日程/会议/转写/投递/岗位）
        + 写：能向外部系统提交动作（极少；v1.0 基本不做外部写）
        + 标签：这一份数据是真的、还是人工、还是连不通（三维：provenance / trigger / connection）
```

**硬规则**：外部能力必须**诚实标注**（真的就是真的，读不到就说读不到，连不通就说连不通）。**禁止**用 Fixture 冒充真实。

## 6. AI 行为纪律（治"傻逼"的硬规定）

这是本轮最重要的一条：**AI 的负面必须靠纪律压住，而且纪律要写下来、可检查。**

### 6.1 输出结构固定（治"问三次三个答案"）

每个环节的输出固定三段：**结论一句 → 依据（引用哪份材料/哪条岗位要求）→ 建议下一步**。
结构固定能显著收敛发散；**不要求回答死板**，允许表达差异，但骨架一致。

### 6.2 绝对禁止的话术（反向免责）

- ❌「这里缺什么」「材料不全」「不能代表…」「不足以判断…」「没有可定位的原文证据」
- ❌ 读不到就堆一堆免责说明，然后不给结论
- ❌ 主动索要材料 / 要求人补录系统没读出来的字段 / 让人"检查结构化结果"
- ❌ 把内部编号、哈希、字段名、接口路径、机器码说给人听
- ❌ 把"两个版本不一致"这类内部冲突解释成需要人去解决的难题

✅ 正确做法：读不到就**一句话说事实**（"这条没读到"），然后**继续往下做**。

### 6.3 承载方式（DSH 原生，不自研）

用 DSH 的 **skill 文件**（`dsh/dsh-recruitment/skill/<环节>/`）承载，一个环节一份，仓库内可版本化、可复盘、可用自然语言迭代：

```
skill/recruitment-s6-intake/
skill/recruitment-s7-screening/
skill/recruitment-s8-interview/
skill/recruitment-s9-transcript/
skill/recruitment-s10-decision/
```

每份固定三段：**这一步要产出什么 → 必须遵守什么 → 绝对不许说什么**。
> 具体措辞**待打磨**（需要大量样本调优），见 §7；本节只固定"载体与骨架"。

### 6.4 用词（产品语言，`docs/17` D-145）

对外——**界面文案、Agent 说给人听的话、skill 工作说明书、`docs/26`**——**不用「证据」**。它带定罪意味（取证 / 举证 / 证据链），会把产品与候选人放到对立面；它本身也是工程词被搬进了产品话。按场景改说：

| 要说的事 | 说成 |
|---|---|
| 材料里的原话与位置 | **原文 / 原话 / 出处**（"第 2 页第 3 行，原话是……"） |
| 对上岗位标准某一条 | **对应 / 对照**（"这条要求，材料里有对应 / 没有对应"） |
| 三态 | **有对应 / 没有对应 / 读不出来** |
| Agent 为什么这么建议 | **依据 / 理由** |
| 工程属性（哈希、定位唯一、逐字命中） | 对外只说 **可复核** |

**不适用范围**：代码字段名（`evidence`）、`docs/17` 台账、验收报告 L1–L6、§6.2 的禁止话术清单（引用原话）。

## 8. 验收口径 v2（**只认这六条**）

> 一份交付是否"做完"，看这六条；**不再**用 73 项矩阵、12 阶段清单、角色视图矩阵、CI 状态判定。

| # | 门 | 判据（人话） | 工程事实 |
|---|---|---|---|
| **V1** | **上下文闭环** | 以人为单位，简历 → 岗位 → 面试 → 面评 → 决策能串起来读得出，且三处（界面/Agent 回答/数据库）说的是同一件事 | 结构化投影一致；独立 psql 读回；无"同一事实多个口径" |
| **V2** | **Agent 辅助到位且不傻逼** | 结构化、对岗位标注、给建议；**不出现 §6.2 任何禁止话术**；不索要材料；不暴露内部标识 | 真会话里逐句可机检（关键词 + 人工判读） |
| **V3** | **人的闸门** | 批准、面评、决策都由**真实人**在真实界面点；Agent 不代劳、不绕过；拒绝时零写入 | 浏览器操作 + 独立 psql 读回 + 负例零写入 |
| **V4** | **外部事实诚实** | 真实外部事实有就是有、没有就标没有；标签三维不撒谎 | 真 artifact id/bytes/sha256；两次读取一致；失败路径 fail-closed |
| **V5** | **看得见** | HR 能一眼看出"今天要干什么、卡在哪、这个人到哪一步"；DSH 的 token/缓存/上下文/额度、任务进度能看到；原文**按需**点开 | 真 Host + 真浏览器 + 截图；数据来自 DSH 与 PG，不自建计量 |
| **V6** | **长任务可恢复** | 长任务跨会话；中断后同一任务能续、尝试次数递增、最终有真实结果 | 同 task_id、attempt 递增、有真实产物 |

**不构成验收项的**：CI 红绿、测试数量、代码行数、阶段覆盖率、角色数量、界面美观度（布局视觉属设计未定）。

> **操作层**：本节只定"判什么"。**"怎么验到"（逐条判据、取证层、反例、来源）见 `docs/29-acceptance-standard.md`**（`docs/17` D-152：标准先行、交验单按它逐条打勾）。两者冲突以本节为准。

## 10. 一句话总结

**以人为单位存上下文，用 Agent 把上下文变成人能快速看懂、快速判断的东西，人的判断留在人手里，外部的世界只接进来不接管。**
