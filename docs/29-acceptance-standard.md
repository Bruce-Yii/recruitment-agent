# 29 · 验收标准（操作层）：链路 × 六门 × 工程

> **这份是什么**：`docs/24 §8` 六条门 V1–V6 是**上位口径**（判什么）；本文是**怎么验到**（判据、取证、反例），
> 提前定好，**开发时就能自查，验收时逐条打勾**。
> **不是**：新的验收哲学、也不是 73 项矩阵复活。**每一条都标来源**（`docs/24` / `docs/17` 裁决 / 真实现场），
> 没有来源的条目一律不许进来——这是"不许乱想"的硬约束。
> **前端不在本文范围**：界面交互与视觉由前端/设计负责；本文只判"后端事实与前端显示是否一致"。

## 0. 三条总则（先看这个，否则会用错）

1. **PASS 只能由独立窗口给**（`docs/17` D-138）。总控、lane、测试都不自证。
2. **机检（全量/两道脚本/tsc/构建）是底线，不是验收**（`docs/24 §8` 末段）。六门任何一门缺，机检全绿也是 FAIL。
3. **一条判据合格的定义** = 第三方拿本文能独立复跑，且结论不依赖当事人自述（`docs/17` D-110 的三条件同样适用于证据本身：可定位、可复算、不靠转述）。

## 2. 证据分层（每条判据都要指到一层）

| 层 | 名称 | 怎么取 |
|---|---|---|
| **L1** | 可达性 | 真会话/真请求 + `file:line`（证明入口真的会调到这里） |
| **L2** | 业务真相 | 独立 `psql` 读回（**不 import 产品代码**），比较调用前后行数/版本 |
| **L3** | 外部事实 | 真 artifact：`id + bytes + sha256`，两次读取一致 |
| **L4** | 人的判断 | 真浏览器真点（截图 1440/390 + body 文本 + 事件时间戳） |
| **L5** | 反证 | 造错版本 / 错配 / 越权 / 缺前置 → **fail-closed 且零写入** |
| **L6** | 机检 | 干净库全量四数 + `runtime-budget` + `clean-load` + `tsc` + 构建产物 |

> 一条判据写 PASS 时，**必须写清它属于哪一层**。只给 L6 = 什么都没验收。

### 3.6 人工逐条纠偏（OV）

> 背景：AI 对岗位标准某一条判错了，人现在只能整条"通过/不通过"。纠偏 = **追加人工修正、不覆盖 AI 原判**，读的时候两者都在。

| ID | 判据 | 取证 | 反例 | 来源 |
|---|---|---|---|---|
| **OV-1** | **追加不覆盖**：纠偏后原 AI 判定仍可读、未被改写；库里是新增行（旧行只被标记 superseded） | L2 前后读回 + 行数 | 原判定被 UPDATE 掉 → FAIL | `docs/32` 原则二 |
| **OV-2** | **有效值正确**：`effective_state` = 最新人工值；同一维度再改一次，只有最新一条是 current | L2 读回 | 同时两条 current → FAIL | 同上 |
| **OV-3** | **未授权零写入**：缺 `confirmation_text` / 未绑定身份 / `criterion_key` 不在该申请钉住的 rubric 内 → 拒绝且逐表行数不变 | L5 + L2 | 写进去了 → FAIL | D-114 / D-115 |
| **OV-4** | **幂等**：同一维度同一值重复提交，不产生第二条 current | L2 | 冒出两条 current → FAIL | D-128 |

### 3.8 HTTP 写入口（HX）与异步上传（ASYNC）

> 背景：能力在 Agent 工具里已有，但前端只能用 HTTP。**同一能力两个入口，行为必须一致**——不许 HTTP 一条、Agent 另一条。

|---|---|---|---|---|
| **HX-1** | **同一能力两个入口一致**：HTTP 动作与同名 Agent 工具走**同一个域函数**（不是复制一份逻辑），返回语义一致 | L1 + 代码路径 | 两份实现各自演化 → FAIL | R1 / R2 |
| **HX-2** | **人的闸门不因换入口而消失**：HTTP 写必须带 `confirmation_text`，服务端算哈希；未绑定身份 / 越权 → fail-closed **零写入** | L5 + L2 行数 | 走 HTTP 就能不确认 → FAIL | D-111 |
| **HX-3** | **既有闸门不被绕开**：新建岗位仍需岗位标准审批；跨岗仍只认同一个人；约束仍受文本上限 | L5 | 为"能建/能转"放宽 → FAIL | AT-2 / D-79 |

| **LOCK-1** | **传旧版本 → 拒绝零写入**：带 `expected_record_version` 且落后时返回 409 `STALE_RECORD_VERSION`，`detail` 含 expected/actual，**零写入、零审计** | L5 + L2 行数 | 覆盖成功 → FAIL | `docs/34 §1.2` |

## 8. 判定规则（避免"看起来都过了"）

- **PASS**：六门（V1–V6）**全部** PASS 且负例 N1–N14 全部符合预期，且 E 类无 FAIL。
- **FAIL**：任一门 FAIL；或任一负例出现写入；或三处（界面/Agent/DB）对同一事实说法不一。
- **BLOCKED**：外部条件不可用（如 provider 429）且**不是**本项目处置范围；必须写恢复路径。**不得**用 BLOCKED 代替 FAIL。
- **NOT_RUN**：没跑。**不计入通过**，单独列。
- **部分绿不算绿**：`skipped>0` 必须逐条给理由；`fail>0` 直接 FAIL，不接受"就一条"。
- **谁给结论**：独立窗口。总控只提供证据与复跑路径，不预判。
